# 최종 측정 사전 등록 — 초기(v0) 대 최종 버전

- 작성: 2026-10-02. 이 파일과 측정 도구의 해시는 `baseline_final.json`에 잠그고, 기록은 `eval/generator_grounding/AMENDMENTS.md` 사슬에 이어 쓴다.
- 목적: 포트폴리오 헤드라인 "초기 베이스라인 대비 최종 결과"를 **같은 입력 · 같은 측정 도구 · 설계에 쓰지 않은 데이터**로 한 번 잰다.
- **최종 측정은 한 번만 한다. 결과가 나쁘면 그대로 보고하고, 고쳐서 다시 재지 않는다.**

## 1. 조건

- **잠금 파일 수정 절차:** 측정 도구 파일은 v0 · 최종 메시지의 **측정 결과를 보기 전에만** 고칠 수 있다. 고칠 때마다 사유 · diff 요약 · 새 해시를 AMENDMENTS("최종 측정 도구 수정")에 남긴다. 실행 때 대조는 "마지막 기록의 해시와 같음"으로 한다. 측정 결과를 본 뒤의 수정은 탐색적으로 표시하고 헤드라인 숫자에는 반영하지 않는다.

## 4. 지표와 검정

- **헤드라인:** 9개 유형 근거 없는 상품 주장이 1개 이상인 메시지 비율.
  - LLM 기준: 검증기 `class`가 양성 또는 재검토인 메시지 비율. 95% Wilson CI.
  - 사람 확인 반영: 아래 6절의 층별 가중 비율, 층별 부트스트랩 95% CI(10,000회, 시드 20261003).
  - 짝 비교 v0 → 최종: 불일치 쌍 25 미만이면 정확 이항, 아니면 McNemar(연속성 보정).
- **보조:** 주 지표(특성어긋남 · 근거없는고민연결, LLM `class_primary` 기준과 사람 확인의 유형 칸 기준), 유형별 건수, 판정기 5개 점수, 목적 전달(검증기 `purpose_conveyed`).
- **비열등(품질 유지 주장의 조건):** v0 대비 짝 부트스트랩 단측 95% 하한이 여유 이상이어야 한다. 판정기 통과율 −0.15, personalization · cta_clarity · tone · accuracy −0.3, 목적 전달 −0.15. **하나라도 못 넘으면 "품질 유지는 확인하지 못했다"와 해당 지표 수치만 쓴다.**

## 5. 최종 버전 선택 규칙(v3 개발 반복)

- 개발은 2라운드 새 표본 70건에서 한다(탐색적). A단계(생성 · 판정기 · 정규식) 재시도 최대 2회, B단계(검증기) 재시도 최대 1회.
- 상한 안에서 A · B를 모두 통과한 가장 최근 버전이 최종 버전이다. 통과한 버전이 없으면 **v1(1라운드 수정, `576c89c`)이 최종 버전**이다(fitter 없음).
- 최종 버전이 v1인 경우의 보고 문구: **"이 경우 최종 결과는 1라운드 수정만의 효과이며 v2 · v3는 채택하지 않았다."**

## 6. 사람 확인

- 도구: `human_final.py` · `check_tool_final.py`(9개 유형 전체 정의와 경계 사례를 화면에 보인다). 조건은 코드(P001…)로 가리고 순서를 섞는다.
- 층: 검증기 9개 유형 기준 `class`(양성 · 재검토 · 음성).
- 배분: **양성 · 재검토는 두 조건 전부**, 음성은 **조건별 12건**(시드 20261012 무작위, 모자라면 전부).
- 기록: 근거 없는 주장 O/X, O이면 **근거 문장 번호와 유형(9개 중 복수 선택)이 필수**, 목적 전달 O/X, 메모. 한 번의 확인으로 헤드라인(9개 유형)과 주 지표(유형 칸에 특성어긋남 · 근거없는고민연결이 있는 O)를 모두 계산한다.
- 사람 반영 비율 = Σ(층 크기 × 그 층 사람 확인의 O 비율) / n. 확인 칸이 빈 층은 없게 한다(전부 확인 · 음성 12건).
- 음성 12건이 0/12여도 Wilson 상한이 약 24%라 구간이 넓다. 그래서 점추정과 함께 층별 부트스트랩 CI를 반드시 싣는다.
- 1라운드 사람 확인의 음성 층 결과(수정 전 0/10 · 수정 후 0/10)는 검증기 설정(high · 8개 유형)이 달라 합치지 않고 **참고값으로만 인용**한다.

## 7. 보고 문구

- 두 줄: "LLM 기준 초기 X% → 최종 Y% (95% CI …)", "사람 확인 반영 시 초기 X′% (CI …) → 최종 Y′% (CI …)" (각 n건, 같은 입력).
- 단계별 개선은 라운드별 결과 표로 따로 쓴다(1라운드 v0 → v1, 2라운드 v1 → v2, 3라운드 v2 → v3). 라운드마다 표본 · 검증기 설정이 달라 라운드끼리 수치를 직접 비교하지 않는다.

## 8. 한계

- 최종 n = 70이라 비율 CI가 넓은 편이다.
- 페르소나 중복(2절).
- 사람 확인의 눈가림은 코드 수준이다. v0와 최종 메시지는 문체 · CTA 형태가 달라 확인자가 조건을 짐작할 수 있다. 판정은 정의 문장과 근거 문구 대조로 하도록 했다(O 판정 시 근거 문장 · 유형 필수).
- 개발 게이트를 통과한 버전만 최종 측정에 가므로 선택 편향이 있다(반복 상한 · 한 번만 측정으로 줄임).
- 생성 · 판정기 · fit 모델은 버전 고정이 없다(두 조건을 같은 시점에 측정, v0는 먼저 생성).
- 효과는 초안 생성 단계 한정이다(피드백 재작성 경로는 fit을 거치지 않는다).
