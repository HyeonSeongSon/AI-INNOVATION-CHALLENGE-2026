# v2 → v3b 근거 지표 악화 원인 분석 (진단, 탐색적)

- 작성: 2026-10-02. 외부 검토 3회를 원자료로 재계산해 반영했다. API 호출 없음.
- 범위: 근거 지표(B단계)를 잰 v3 계열은 **v3b뿐**이다. v3 · v3c는 A단계에서 멈춰 근거 성적을 모른다.
- 모든 주 지표 수치는 **LLM 검증기(medium) 수**이며 사람 보정 전이다. 2라운드부터 사람 확인은 하지 않았다.
- 사전 등록상 최종 버전은 v1로 정해졌다(AMENDMENTS "v3 개발 종료"). 이 분석은 최종 측정에 영향을 주지 않고 다음 라운드 설계 근거로만 쓴다.

## 1. 관측

| | v1 | v2 | v3b |
|---|---|---|---|
| 주 지표(특성어긋남 · 근거없는고민연결) 메시지 수 | 15 | 7 | 16 |
| 9개 유형 | 22 | 11 | 22 |

- v2 → v3b: 나빠진 14건(N010 · N013 · N022 · N023 · N026 · N029 · N032 · N035 · N040 · N046 · N048 · N052 · N056 · N069), 좋아진 5건(N007 · N034 · N050 · N057 · N062). 짝 검정 p = 0.064.
- 목적별: v1 → v2 개선 8건 중 5건이 "피부타입/고민" 목적(7 → 2)이었고 v3b도 3건으로 유지했다. v3b 증가분은 베스트셀러 3 · 성분 3 · 프로모션 2 등 여러 목적에 흩어져 있다. **v2의 개선을 무너뜨렸다기보다 공통 지시가 새 오류를 여러 목적에 퍼뜨린 모양이다.**

## 2. 원인 (재계산으로 확인)

### C1. fit 승인 기준이 검증기 기준과 다르다 (핵심)

- v3b 근거없는고민연결 지적 17개 중 **12개가 fit이 승인한 니즈 위**에서 나왔다(그중 선호 5개). v2도 6개 중 5개(선호 3개). 2글자 겹침으로 맞춘 근사치.
- 선호 연결 사례: N010 "신속한 수정 화장 ← 리필 구성", N046 "메이크업 전 보습 ← 토너 또는 에센스·세럼 사용 후", N069 "샴푸 후 사용 ← 샴푸와 함께 사용", N023 "끈적임 없는 마무리감 ← 부드럽게 흡수되는 텍스처", N048 "산뜻함".
- 선호 연결에는 코드 검사(근거 문구 존재 · 필드 분류)는 있지만 **의미 검사가 없다**. 어휘 규칙은 고민에만 걸렸다. 잠금 전 사람 확인에서도 무관 연결 8개 중 7개가 선호였다.
- 더 근본적인 문제: fit을 검증한 사람 라벨 116개는 "근거가 니즈와 관련 있는가"를 물었다(108개 O). **"이 연결로 쓴 문장이 검증기를 통과하는가"는 묻지 않았다.** 부품을 다른 성질로 검증한 셈이다.
- 승인 후 거부된 12건의 구성(검토자 판단): 약 9건은 fit 연결 자체가 무관하거나 일부만 맞음, 약 3건은 맞는 연결을 생성기가 넓힘(N032 "건성으로", N048 "손·발", N069 "바로").

### C2. fit 안내 형식이 페르소나 쪽 라벨을 "써도 되는 말"처럼 넘긴다

- `build_fit_section`은 `- {페르소나 니즈} → 근거: '{근거 문구}'` 형식으로, LLM이 다듬은 니즈 라벨을 앞에 둔다.
- 주 지표 지적 중 라벨을 글자 그대로 담은 것: **v3b 21개 중 6개**(N032 · N040 · N046 · N052 · N056), v2 7개 중 0개. 근거 문구를 그대로 담은 지적은 3개.
- 메시지 전체 사용 횟수는 라벨 v2 70 · v3b 53, 근거 문구 v2 112 · v3b 171(재계산; 검토자는 라벨 27로 셈). v2는 라벨을 더 많이 쓰고도 지적이 0이었다. 그래서 **라벨 복사 자체보다 v3b의 "한 문장에서 잇기" 지시와 겹칠 때 지적으로 이어진다**고 본다.

### C3. v3b의 연결 지시가 C1 · C2의 오류를 메시지로 옮겼다

- 바뀐 문구: 공통 두 줄(고민-효능 한 문장 연결 · 선호 1~2개 명시) + 신제품 · 성분 목적의 "연결 항목을 새 특징 · 성분과 한 문장에서 잇기".
- 상황 · 대상 적합 문형("~원하시는 분께 적합 · 도움")이 있는 메시지: v1 2 · v2 3 · v3 4 · **v3b 10**(그중 앞 두 문장 8). 검토자 정규식으로는 v1 5 · v2 5 · v3 9 · v3b 14.
- N026 성분-효능 오귀속은 성분 목적 문구와 맞닿아 있다.
- v3 · v3b · v3c는 같은 fit 캐시를 쓰므로 v3 계열 안의 차이는 순수하게 프롬프트 차이다. 반면 **v2 대 v3b는 프롬프트와 fit(코드 변경 + 재실행)이 함께 바뀌었다.**

### C4. fit 출력 형식(스키마)의 빈칸

- "상품 한계" 범주가 없다. 충돌은 선호가 상품 특성과 정반대일 때만 다룬다. N029 · N056(진한 메이크업 크리에이터 × 가벼운 오염용 폼)의 핵심 불일치가 어디에도 기록되지 않았다.
- 연결 가능 ↔ 연결 불가 모순을 검사하지 않는다. N029는 "잔여물 제거"를 연결 가능으로, "진한 메이크업 완전 제거"를 연결 불가로 동시에 냈다. 코드는 연결 가능 ↔ 충돌 모순만 제거한다.
- 복합 니즈를 나누지 않는다(재계산 11개, 검토자 기준 14개). 예: N052 "탄력·영양 공급", 근거는 영양 공급뿐.
- fit 코드 자체가 v2 → v3 사이에 바뀌었다(해시 30b92272 → d4df35a1: 선호 같은 축 규칙 · 고민 어휘 겹침 · 모순 제거). 두 캐시의 니즈 일치도는 Jaccard 0.23(재계산; 검토자 0.29)으로 사실상 새로 뽑은 결과다. 고민 연결 153 → 116 중 22개는 어휘 규칙, 15개는 재실행 몫.

### C5. 안전장치가 작동하지 않았다

- **어휘 규칙:** 무관한 4건을 통과시켰다(N040 "관리" · N056 "이크"(메이크업 ↔ 마이크로) · N029 "제거" · N052 "영양·공급"). 내린 22개 중 약 14개는 타당한 동의어로 보인다(자외선 차단 ← SPF50+, 발냄새 ← 탈취 99.8%, 붉어짐 ← 붉은기 등, 검토자 판단). 통과한 고민 연결 116개 중 **39개는 겹친 글자가 페르소나 원문에 없다**. fit이 니즈를 상품 쪽 단어로 바꿔 쓰면 통과하는 순환 구조다.
- **생성 후 금지어 검사:** v3b 양성 16건 중 **0건** 검출. 금지어가 "눈썹숱증가" · "모발성장촉진" 같은 복합어라 메시지에 그대로 나오지 않는다. 접두어 제거 버그도 있다("즉각적인 진정 효과" → "적인진정").
- **프롬프트 규칙 위반:** 성분-효능 귀속 규칙(v3 추가)을 N026이, "근거 문구 표현 유지"를 N032 · N069가 어겼다. 규칙을 더 쌓는 방식은 효과가 크지 않다는 근거다.

### C6. 측정 · 평가 설계

- **판정기 루브릭 범위:** accuracy는 "상품명 · 성분 · 기능 · 수치 · 인증이 상품정보에 있는가"만 묻고, 페르소나 연결 주장은 범위 밖이다(양성 · 음성 accuracy: v2 5.00 / 4.89, v3b 4.78 / 4.79). personalization은 "고민 반영 · 혜택 강조 · 소구 포인트"만 묻고 근거 조건이 없다. **모델의 실패가 아니라 루브릭 범위 설계의 문제다.** 운영 품질 게이트도 같은 판정기라 이런 주장을 통과시킨다.
- **판정기와 근거 없는 연결의 관계는 판단할 수 없다.** 양성 메시지의 personalization이 v1(4.87 대 4.59) · v2(4.71 대 4.28)에서는 높고 v3b(4.31 대 4.59)에서는 낮다. 근거 있는 연결 수를 통제해도 차이는 v1 +0.30 · v2 +0.44 · v3b −0.23이다(검토자 계산, 미재현). 양성이 7~16건이라 인과를 말할 수 없다.
- **게이트 진동:** A단계 기준인 v1은 근거 없는 연결로 개인화 점수를 얻은 버전이다. A → B를 순서대로 판정하며 한 지표씩 고치다 v3(A 미달) → v3b(B 미달) → v3c(A 미달)로 돌았다. v3 진단("판정기가 연결을 보상")에 대한 처방이 연결 지시를 더하는 쪽이었던 것도 진동을 키웠다.
- **잡음:** 버전마다 생성 1회. v1 → v2(12 대 4, p = 0.077), v2 → v3b(p = 0.064), v1 → v3b(좋아짐 10 · 나빠짐 11)로 메시지 단위 교체가 크다. 7 → 16 중 프롬프트 효과의 크기는 모른다.
- **보정 없음:** PREREG_v2가 이 라운드를 "방향성 확인"으로 격하했다(정밀도 추정 2/7, 95% 구간 8~64%). v2 본 측정 사람 확인은 실행하지 않았다. v3b 양성에는 경계 사례(N032 "건성으로" · N046 사용 단계 · N069 "바로")도 섞여 있다.
- **심각도 구분 없음:** 표기 실수(N052 "성분(…5중 레이어)"), 오해 유발(N029 가벼운 오염용 폼으로 진한 메이크업 제거 약속), 규제 소지(N061 "트러블이 빨리 가라앉고", 의약품 오인)가 모두 1건으로 같다.
- **표본:** 페르소나 × 상품 무작위 짝이라 fit 위험군 70/70, 충돌 있는 짝 56/70(v3 캐시; 검토자 63). 운영 추천기 결과보다 무리한 짝이 많다. 페르소나 19명을 2회씩 썼다(v3b 양성 중 같은 페르소나 짝 N029 · N056).

### C7. fit 추론 강도

- 지연 상한 때문에 minimal로 정했다. 무관 연결 비율은 minimal에서만 쟀다. low는 연결 수가 25% 적었지만(120 → 90) 정밀도는 재지 않았다(지연 중앙값 11.6초).

## 3. 철회 · 수정한 이전 결론

- "v3c에서 해결됐다": 철회. v3c는 "적합 · 도움이라고 말하지 않는다"를 새로 넣어 정규식이 세는 단어를 금지했다. 생성기는 "해답이 될 수 있습니다"(N069) · "원하는 분께 권합니다"(N044) 등으로 바꿔 썼고, N023 "답답한 피부에"는 v3b 지적 문구와 같다. v3c는 검증기로 재지 않았다.
- "개인화와 근거가 같은 손잡이라 프롬프트로는 동시에 못 맞춘다": 철회. personalization 짝 차이 v3b → v3c는 −0.079(90% CI −0.214 ~ +0.057)로 잡음 범위다.
- "판정기가 근거 없는 연결에 가점": "인과 여부는 판단할 수 없다"로 수정(C6).
- 사실 오류: N046에는 고민 연결 1개('진정')가 있다. 적합 문형은 "v3 4건 → v3b 10건"이다.

## 4. 해 봐야 효과가 없을 것 (검토자 계산, 미재현)

- fit을 여러 번 돌려 반복 선택된 연결만 남기기: 거부된 주장의 바탕 연결도 다른 실행에서 다시 뽑힌 비율 62%(8/13), 나머지 61%로 같다.
- 페르소나의 "니즈 · 구매 기준" 줄 따로 처리: 지적 17개 중 9개가 "고민" 줄, 니즈 2 · 구매 기준 1.

## 5. 개선안 (싼 순서)

| 비용 | 개선안 |
|---|---|
| 없음 | fit 안내를 근거 문구 중심으로: "말할 수 있는 효과 = '근거 문구'", 페르소나 고민은 공감 훅으로만 |
| 없음 | fit 코드에 복합 니즈 분리, 연결 가능 ↔ 연결 불가 모순 검사, "상품 한계" 범주 |
| 없음 | 원인별 회귀 세트: fit 승인 후 거부 12건 + 어휘 규칙 오통과 4건 + 잘못 내린 동의어 약 14건. 확인 계획 4단계는 116개 라벨 대신 이 세트로 |
| 없음 | 금지어 검사를 문장 단위 근거 검사로 바꿔 재생성 루프에 연결(접두어 버그 수정 포함) |
| 낮음 | fit 연결마다 검증기와 같은 정의(GROUNDING_DEF)로 "이 연결로 쓴 주장이 근거 있는가" 확인 |
| 낮음 | fit low · medium을 같은 라벨 세트로 측정. 페르소나 · 추천 상품이 정해질 때 fit을 미리 계산해 지연 상한 문제 해소 |
| 설계 | A단계를 "근거 있는 개인화" 기준으로 재정의하거나 A · B 동시 판정 · 표본을 추천기 상위 결과에서 뽑거나 fit 위험도로 층화 |
| 판정기 변경 | accuracy 범위에 페르소나 연결 주장 포함, personalization에 "근거 있는 연결만 인정". 게이트 정의가 바뀌므로 AMENDMENTS에 먼저 기록 |
