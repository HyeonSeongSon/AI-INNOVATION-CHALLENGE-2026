# V4 최종 시험 사전 등록 — 초기(v0) 대 V4, 한 번만

결과를 보기 전에 잠근다(`final_v4.py lock`). 잠금 뒤 도구 수정은 결과를 보기 전에만 허용하고, 사유와 새 해시를 AMENDMENTS("V4 최종 측정 도구 수정")에 남긴다. 결과를 본 뒤에는 고치지 않고 한계로 적는다.

## 1. 채택과 이 시험의 관계
- 최종 버전은 V4로 이미 확정했다(AMENDMENTS 33 "V4 최종 버전 확정"). 이 시험 결과는 채택을 바꾸지 않는다.
- 이 시험에는 v3R이 없다. 그래서 V4 대 v3R의 증분은 판정하지 않는다.
- V4의 LLM 비율이 v3R 최종(10.0%, 다른 표본)보다 높게 나와도 CI와 함께 그대로 보고한다. 표본이 달라 직접 비교할 수 없다고 명시한다.

## 2. 표본
- 예약 상품(`v4_reserved_final_products.json`, AMENDMENTS 21)에서 v3 최종과 같은 뽑기 규칙으로 뽑는다.
  - 규칙: 같은 상품 종류 안에서 무작위, 페르소나는 표본당 최대 2회, 목적 7개 순환
  - 시드는 20261021, 목표는 85건이다.
- **부위 맞춤(추가 규칙):** 부위가 갈리는 상품 종류(핸드&풋케어)는 페르소나의 부위(손 · 발)와 상품명의 부위가 같은 짝만 쓴다.
  - 페르소나 정보에 손과 발이 모두 있으면 둘 다 허용한다.
  - 상품명에 부위가 없으면 허용한다.
- 뽑은 상품이 예약 목록의 부분집합인지 대조한다. 표본 용량 확인 결과(잠그기 전 건수만 셈)는 4절에 적는다. 확보 건수가 70건 이상이면 그대로 진행한다.

## 3. 조건과 측정
- **v0:** e967b13 프롬프트 + v3R 스냅숏 생성기(fitter 없음, 원본 페르소나, 생성 뒤 점검 없음). `v0_generator.py`가 담당한다.
  - 모델 폐기 위험 때문에 먼저 생성하고, 내용은 열지 않는다.
- **V4:** 운영 생성기(AMENDMENTS 33의 5개 파일 해시와 같을 때만 실행)
  - 실제 PersonaFitter(연결 확인 켬), 거른 페르소나, 승인 연결만 넣음, 점검 A와 1회 재생성
  - fit · 연결 확인 · 점검 결과를 저장한다.
- **검증기:** measure_v2 그대로, gpt-5.5 medium. v0와 V4를 같은 시점에 돌린다.
- **판정기:** gpt-5-mini, 2회. v3 최종과 같은 설정이다.

## 4. 표본 용량 확인 (잠그기 전)
- 확보 가능 건수: **85건**(목표 85, 최소 70). `final_v4.py capacity`, 2026-10-06, 건수만 셈.
- 뽑힌 상품은 모두 예약 목록 안에 있다(부분집합 확인).
- 예약 상품에는 핸드&풋케어 종류가 없다. 그래서 부위 맞춤 규칙이 적용되는 짝은 0건이다(규칙은 유지).

## 5. 지표와 보고 (모두 보고용 — 채택에 쓰지 않음)
- **헤드라인:** 근거 없는 상품 주장(9개 유형)이 1개 이상인 메시지 비율. LLM(양성 + 재검토), Wilson 95% CI를 쓴다.
  - 짝 비교는 McNemar(연속성 보정)다.
- **주 지표:** 특성어긋남 + 근거없는고민연결 비율. 헤드라인과 같은 방식으로 낸다.
- **사람 확인 반영 비율**
  - 층별 배분은 v3 최종과 같다. 양성 · 재검토는 전부, 음성은 조건마다 무작위 12건(시드 20261021)이다.
  - 버전을 가리고 섞는다. 메시지 단위로 기준표(`HUMAN_RUBRIC.md`, AMENDMENTS 23 보완판)의 주장 판정을 한다. 애매는 O 쪽으로 세지 않고 따로 표시한다.
  - 층 크기로 가중하고, 층별 부트스트랩 95% CI를 낸다.
- **품질 비열등 (v0 대비 짝 부트스트랩 단측 95% 하한)**
  - 여유: 통과율 −0.15, 개인화 −0.3, CTA −0.3, tone −0.3, accuracy −0.3, 목적 전달 −0.15
  - 기준을 옮기지 않는다.
  - **개인화 예측:** (가) 짝에서 약 −0.17, 공통 언급 짝에서 약 −0.19가 남아 전체 비열등은 미달 가능성이 높다(AMENDMENTS 22).
- **2차 사전 등록 지표**
  - 맞는 짝 층의 개인화 비열등(v0 대비 −0.3)
  - 근거 있는 개인화 비율(`metrics_v4.py`)
  - 짝 층은 V4 fit 결과로만 정한다(고민 연결 1개 이상 = 맞는 짝). 생성물과 무관하다.
- **보고용:** 안 맞는 짝 층의 개인화, 재생성 비율, 형식 위반, fit 상태, 연결 확인 상태
- **잔존 오류:** 원인 ①(fit 오승인)과 ③(효능 출처 혼동)은 0~2건 남는 것을 전제로 보고한다.

## 6. 측정 범위와 한계 (보고서에 그대로 적는다)
- 측정은 생성 단계에 한정한다. 운영의 품질 게이트 뒤 재작성은 측정하지 않는다. 단계 2의 재작성 점검 결과가 있으면 함께 인용한다.
- 결과를 본 뒤 바꾼 결정 3건
  - 연결 확인 지연 기준을 7.0초에서 8.0초로 완화했다(AMENDMENTS 29).
  - 점검 A 켜기 판단에 사람 확인을 추가했다(AMENDMENTS 30).
  - 채택 규칙을 근거 우선으로 바꿨다(개인화를 보고 지표로 전환, AMENDMENTS 33).
- 단계 2 근소 미달(재생성 비율 10.7%, 형식 위반 1건)은 버전 파일을 고치지 않고 공개했다.
- 평가 표본은 추천 결과가 아니라 같은 상품 종류 안에서 무작위로 짝지은 것이다. 그래서 운영보다 짝이 덜 맞을 수 있다.
